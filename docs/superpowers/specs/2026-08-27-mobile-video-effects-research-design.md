# 手机录像特效玩法库设计

日期：2026-08-27

## 1. 目标

在 `daily/20260827_录像特效调研` 下建立独立的手机录像特效研究库。它不延续此前以画质、稳定、ISP 工程链路为中心的分类，而以用户能够直接看到、操控和分享的视觉特效为中心。

核心问题不是“视频处理得更稳或更清楚”，而是：

- 录制过程中画面发生了什么明显、有趣的变化；
- 用户能否通过视线、动作、表情、声音、触摸或手机运动控制变化；
- 特效如何跨帧持续演化，而不是逐帧贴图；
- 录后能否重设轨迹、强度、颜色、时间、对象和生成范围；
- 能否形成适合手机录像传播的新玩法。

实时光绘轨迹和视线矫正作为首批重点案例，代表两类核心路线：世界空间中的时序轨迹特效，以及人脸语义驱动的实时编辑特效。

## 2. 特效判定门槛

一个方向只有同时满足以下条件，才进入主特效玩法库：

1. 用户可以用一句话说明画面发生了什么可见变化；
2. 变化明显区别于普通画质优化；
3. 至少存在一个交互、时序或语义控制维度；
4. 能形成实时预览、录制在线或录后编辑中的一种完整体验；
5. 不只是把场景、帧率或设备名称替换后重复生成。

普通防抖、去噪、HDR、锐化、超分、色彩一致性、多摄切换和常规自动运镜不进入主玩法库。它们可以作为特效稳定性、分层质量或实时性基础设施被引用。

运镜只保留本身构成视觉特效的方向，例如希区柯克变焦、子弹时间、时间切片、镜面穿越、空间折叠、人物静止而背景旋转。平滑跟拍、普通推拉摇移和自动构图不作为重点。

## 3. 内容架构

采用“特效原子 + 完整玩法 + 组合配方 + 真实参考”四层结构。

### 3.1 特效原子

特效原子是可复用的视觉或交互组件，预计约 120 个，包括：

- 分割：人脸、身体、头发、服装、手部、物体、背景、阴影、反射；
- 几何：2D 轨迹、3D 轨迹、骨骼、深度、表面法线、空间锚点；
- 时间：延迟、冻结、循环、回放、时间衰减、轨迹积累、异速；
- 光效：发光、星芒、flare、轮廓光、追光、眼神光、投影、体积光；
- 复制：残影、分身、动作切片、时间克隆、镜像人格；
- 形变：液化、拉伸、空间折叠、漫画速度线、局部透视；
- 材质：金属、玻璃、液体、火焰、霓虹、像素、纸张、织物；
- 粒子：烟雾、火花、花瓣、雨雪、文字、音乐频谱、碎片；
- 生成：服装、发型、年龄、角色、天气、背景世界和风格变化；
- 触发：视线、眨眼、表情、嘴型、手势、姿态、声音、节拍、触摸、手机运动。

原子不是最终产品 IDEA。只有当它与明确对象、时序行为、触发和用户控制组成体验时，才成为完整玩法。

### 3.2 完整玩法

预计约 300 个独立玩法，按用户看到的效果分为：

1. 光轨、光绘与动态光学；
2. 人体残影、分身与动作轨迹；
3. 人脸、视线、表情与五官驱动；
4. 时间冻结、异速与局部时间编辑；
5. 空间折叠、镜面穿越与维度变化；
6. 虚拟灯光、影子与轮廓光；
7. 材质替换、溶解与形态变化；
8. 粒子、天气与自然现象；
9. 背景世界、场景风格与现实改写；
10. 声音、节拍、歌词与声源可视化；
11. 特效型摄影与镜头语言；
12. 多人互动、接力与协同特效。

### 3.3 组合配方

预计约 200 个组合配方。每个配方必须由两个或以上已经定义的原子或完整玩法组成，并解释组合后新增的用户效果，不能只是名称拼接。

示例：

`手部轨迹 + 世界空间锚点 + 发光衰减 + 节拍调色 = 节拍驱动实时光绘`

`视线估计 + 瞳孔重定向 + 眼神光重渲染 + 对话对象识别 = 多人采访智能对视`

`人体分割 + 时间克隆 + 姿态差分 + 颜色分层 = 舞蹈动作分身谱`

### 3.4 真实视觉参考

真实参考只负责帮助理解效果和技术边界，不要求每个原创 IDEA 都有完全相同的现成产品。

来源优先级：

1. 手机厂商、相机厂商和社交影像产品的官方演示；
2. Adobe、Blackmagic、Apple、CapCut、TikTok、Snap、Meta 等软件或平台的官方效果；
3. 电影、MV、广告和舞台视觉中的代表性效果；
4. 论文原文定性结果、项目页和作者演示；
5. 游戏引擎、AR 工具和视觉特效软件的官方示例。

引用时必须区分：手机实时效果、桌面离线效果、影视后期效果、研究原型和仅视觉灵感。不能把影视效果写成已在手机实时实现。

## 4. 重点玩法

从完整玩法中选约 50 个进行深度拆解，优先选择：

- 视觉差异强，用户无需解释即可理解；
- 能通过手机已有传感器或模型进行交互；
- 实时预览具有即时反馈；
- 录后仍有可编辑空间；
- 适合短视频、Vlog、舞蹈、演唱会、人像、宠物、儿童或多人创作；
- 与现有滤镜相比有新的时序、空间或语义能力；
- 有真实视觉参考或可核实的相邻技术。

首批重点方向包括：

- 实时光绘轨迹；
- 人体动作光轨；
- 世界空间霓虹书写；
- 视线矫正与虚拟对视；
- 眼神光随视线移动；
- 表情驱动材质变化；
- 眨眼触发场景切换；
- 人体残影和时间分身；
- 局部时间冻结；
- 人物与背景异速；
- 动态星芒和节拍 flare；
- 虚拟追光和影子分身；
- 人体粒子化与局部溶解；
- 镜面穿越和空间折叠；
- 声音实体化和歌词环绕；
- 多人能量传递与动作接力；
- 希区柯克变焦、时间切片和受约束子弹时间。

## 5. 单玩法数据结构

每个完整玩法至少包含：

- 稳定 ID 与中英文名称；
- 所属特效族；
- 一句话视觉效果；
- 典型使用场景；
- 作用对象和空间范围；
- 触发信号；
- 实时交互方式；
- 用户可调参数；
- 实时预览流程；
- 录后高质量流程；
- 所需 Mask、深度、姿态、光流、人脸、视线、音频或 IMU；
- 所依赖的特效原子；
- 跨帧状态和时间窗口；
- 时序连续性难点；
- 端侧实现难度；
- 推荐执行位置：ISP、GPU、NPU、VPU、录后端侧或云端；
- 生成式程度：忠实编辑、感知特效或生成式改写；
- 身份、几何、事实和版权风险；
- 真实参考及证据类型；
- 可组合玩法；
- 新鲜度、传播性和产品价值判断。

## 6. 交互模型

特效设计应优先考虑主动控制，而不是只有自动套用：

- 视线：注视方向、注视对象、眨眼、凝视时长；
- 面部：表情、嘴型、头部姿态、眉眼变化；
- 身体：手势、骨骼姿态、运动速度、动作阶段；
- 声音：音量、频谱、节拍、歌词、声源方向、说话人；
- 触摸：画线、选择对象、设定锚点、擦除和关键帧；
- 手机运动：旋转、平移、摇晃、靠近、远离和空间扫描；
- 多人关系：视线交汇、触碰、接力、距离和相对姿态。

每个重点玩法都应说明交互失败时的降级方式，例如视线置信度低时逐渐减弱，而不是瞬间跳变。

## 7. 实时与录后双轨

每个重点玩法分别设计：

- 实时预览版：低延迟、低分辨率代理、简化粒子、短时间状态；
- 录制在线版：保存 Mask、轨迹、深度、姿态、视线和音频控制信号；
- 录后端侧版：重算边界、阴影、遮挡、粒子密度和时间轨迹；
- 可选云端版：生成式换装、世界重构、复杂材质和长时间一致性。

实时预览不必等同最终质量，但必须保持特效位置、触发时机和总体形态一致，避免录后结果与拍摄预期完全不同。

## 8. 风险表达

全面允许生成式特效，但每条玩法必须显式标注：

- 身份漂移：脸、体型、服装和动作主体是否改变；
- 时序漂移：纹理、粒子、材质和背景是否闪烁或游走；
- 几何错误：手指、眼睛、遮挡和反射关系是否破坏；
- 事实改写：人物、文字、品牌、地点和事件是否被生成修改；
- 交互误触发：视线、表情、手势和声音识别是否导致错误效果；
- 光敏风险：高频闪烁和强对比节拍特效是否需要限制；
- 版权与肖像：角色化、风格化和素材引用是否需要授权。

风险不是排除生成式玩法的理由，而是确定默认强度、保护区、回退策略和导出标记的依据。

## 10. 预期规模

- 约 120 个特效原子；
- 约 300 个独立完整玩法；
- 约 200 个组合配方；
- 约 50 个重点深度拆解玩法。

这些是内容目标，不通过复制对象、场景、帧率和部署位置机械凑数。最终数量允许根据去重和质量审查调整。

## 11. 验证标准

- 每个完整玩法都能用一句话描述可见效果；
- 每个玩法至少包含一个触发或控制维度；
- 每个玩法依赖至少一个已定义特效原子；
- 所有 ID 唯一且引用有效；
- 不把普通防抖、去噪、HDR 或常规运镜作为主玩法；
- 组合配方明确说明组合后的新增效果；
- 重点玩法完整包含实时与录后双轨；
- 生成式玩法有身份、时序、几何和事实风险；
- 真实参考明确标记来源类型和手机实时可行性边界；
- Excel、Markdown、Word 与 JSONL 数量一致；
- Word 经过结构检查和页面渲染复核；
- 报告优先展示视觉效果、交互和玩法价值，算法解释服务于体验而不是取代体验。
