# 手机录像后处理 IDEA 全量宇宙设计

日期：2026-08-27

## 1. 目标

在 `daily/20260826_后处理调研` 下建立独立的创意型数据库。该数据库不替代已有的 112 条证据型机会库，也不要求每条 IDEA 都有论文或产品来源。核心目标是最大化手机录像玩法、后处理能力、交互方式和系统架构的探索空间。

## 2. 内容分层

1. `Legacy 112`：完整导入已有机会库，保留原始 ID。
2. `Prior Brainstorm`：保留此前对话中列举的计算底片、对象级快门、动态星芒、虚拟打光、多摄、声音驱动、可信生成等方向。
3. `New Native Ideas`：从手机传感器、ISP、时序记忆、语义对象、空间信息、声音和端侧系统重新提出基础创意。
4. `Cross-Domain Combinations`：迁移电影制作、体育导播、AR、机器人、自动驾驶、游戏引擎、广播和编解码领域的能力。
5. `Controlled Variants`：对每个基础 IDEA 沿单一维度展开变体，不把变体冒充独立基础发明。

## 3. 基础 IDEA 判定规则

基础 IDEA 至少改变以下一项：

- 用户最终看到或控制的录像效果；
- 被处理的语义对象、材质、时间区域或空间区域；
- 拍摄时新增使用的手机信号；
- 实时拍摄、录制、录后重算或交付文件的系统链路；
- 用户与自动摄影系统的交互方式；
- 忠实恢复、感知增强或生成式创作的边界管理方式。

仅改变实时/录后、30/60 fps、全画面/ROI 或文件格式的记录归入变体库。

## 4. 变体轴

每个基础 IDEA 分别生成以下单轴变体：

- 处理阶段：实时预览、录制在线、录后端侧、云端高质量；
- 真实性：忠实恢复、感知增强、生成式创作；
- 输入：单摄、双摄、深度、IMU、音频、多设备；
- 场景：人像、宠物、儿童、运动、夜景、演唱会、旅行、直播；
- 时间规格：30 fps、60 fps、高帧率慢动作、长时间录像；
- 处理范围：全画面、ROI、关键帧、低功耗代理；
- 交付形态：即时分享、专业母版、可编辑工程、端云协同。

采用单轴展开而非全笛卡尔积，避免生成数百万条不可读组合。后续可以按需将两个或三个轴继续组合。

## 5. 数据结构

基础 IDEA 包含：稳定 ID、中文名称、能力族、创意簇、来源层、用户效果、核心机制、手机独有价值、输入信号、适用场景、默认真实性、时序跨度、风险和标签。

变体记录包含：基础 IDEA ID、变体轴、变体值、变体名称、实现解释、处理阶段、输入、场景、帧率、处理范围、交付形态和风险提醒。

## 6. 输出

- `metadata/idea_universe/core_ideas.jsonl`
- `metadata/idea_universe/idea_variants.jsonl`
- `metadata/idea_universe/idea_universe_stats.json`
- `report/手机录像后处理_IDEA全量宇宙_20260827.md`
- `matrix/手机录像后处理_IDEA全量宇宙_20260827.xlsx`

Excel 提供总览、基础 IDEA、变体库、既有方向、新增方向、按能力族统计、按场景统计和变体字典。所有记录显式标记为 `idea_only`，不能与已有 E1-E4 证据型结论混淆。

## 7. 验证

- 基础 IDEA ID 与变体 ID 唯一；
- 每个旧机会 ID 均被纳入；
- 前述关键方向均能通过标题或标签检索；
- 每个基础 IDEA 都有完整的变体轴覆盖；
- Excel 行数与 JSONL 一致；
- 对所有工作表渲染代表性区域并视觉复核；
- 不虚构论文、产品成熟度、端侧 FPS 或功耗数字。
